# Custody signer child policy

This policy applies to `assoc-exec`, `recovery-exec`, and `mint-exec`.

Each purpose uses two nonsecret bindings read from that purpose's trusted
Doppler config with the same authentication used for its existing custody
bindings:

| Purpose | Path binding | Hash binding |
| --- | --- | --- |
| Association | `ASSOC_SIGNER_PATH` | `ASSOC_SIGNER_SHA256` |
| Recovery | `RECOVERY_SIGNER_PATH` | `RECOVERY_SIGNER_SHA256` |
| Mint | `MINT_SIGNER_PATH` | `MINT_SIGNER_SHA256` |

An owner enrolls these bindings after reviewing the signer executable and its
SHA-256 digest. Enrollment is an owner operation; this CLI change does not
enroll pins or assert that a service-token reader cannot independently
reconstruct custody material.

The configured path must be absolute and exactly equal to command[0]. The hash
must contain exactly 64 lowercase hexadecimal characters. Missing bindings,
path mismatches, malformed hashes, and extra arguments fail before seed
download or unseal.

On Linux, validation opens the executable without following symlinks. The
opened file must be regular, root-owned, and have no group or other write bits.
Every parent directory, including the root directory, must be a root-owned,
directory without group or other write bits and is opened without following symlinks. Only ELF executables with an execute bit are accepted; interpreter
scripts and other formats are rejected. The SHA-256 digest is computed from the opened file
descriptor. The CLI executes that same descriptor with `fexecve`, so a
pathname replacement after validation cannot substitute another executable.
Validation descriptors not needed by execution are closed.

The child receives only command[0], an empty environment, and stdin containing
exactly the 32 seed bytes followed by EOF. The CLI does not preserve PATH or
accept shell, output, plugin, or other caller-provided options. Non-Linux
execution fails closed.

A Linux integrator witness should use fake Doppler and S3 services plus a tiny
audited signer binary pinned by trusted config. Verify it receives exactly 32
generated bytes and EOF with empty ambient credentials. Verify that `xxd`,
relative PATH, shell commands, extra arguments, hash mismatch, missing pins,
symlinks, writable files or parents, and descriptor/path swaps fail before
seed access and emit no sentinel to stdout or stderr. Planting pathname-based
execution after hashing must make the race witness fail. Replacement after
validation must either execute the validated inode or refuse. Real signer
enrollment and operation remain externally unverified.
